Overview

In plain English: A program for a university advising office. It loads a list of courses from a file, lets someone look up any course and its prerequisites, and prints the full course list in order.

The Course Planner application is a C++ program developed in CS-300 Data Structures and Algorithms. The program loads course information from a CSV file, stores course data, lets users search for specific courses, displays prerequisites and prints course information in alphanumeric order.

This artifact is used for the Algorithms and Data Structures category of the CS-499 Computer Science Capstone.

Features

  • Loads course data from a CSV file
  • Vector for sorted course output
  • unordered_map hash table for fast lookup
  • Search by course number
  • Prerequisite display
  • Alphanumeric course list
  • CSV and duplicate validation
  • Safe menu input

Algorithms and data structures

In plain English: This is the key change. Before, finding a course meant checking the list one course at a time. Now the program also keeps an index, called a hash table, so it can jump straight to any course. That stays fast even as the list grows. The ordered list is still kept for printing.

This project focuses on core data structure and algorithm concepts, including vectors, hash tables, searching, sorting, file parsing and input validation.

  • Case-insensitive course searching

The original implementation stored and retrieved course data using a vector. The enhanced version keeps the vector for sorted course output while adding an unordered_map hash table to improve lookup efficiency.

Enhancement narrative

In plain English: My written explanation, as submitted for the course, of why I chose this project, what I changed, which course outcomes it meets, and what I learned along the way.

Milestone Three: Enhancement Two · CS-499 · May 31, 2026

The artifact I selected for the Algorithms and Data Structure category is the CS-300 Course Planner program. This project was created in CS-300 Data Structures and Algorithms in June 2025. The program is a C++ advising assistance application that loads course information from a CSV file, stores course records, prints all courses in alphanumeric order, searches for a specific course by course number, and displays that course’s prerequisites. The original version of the program used a vector to store course objects and used a linear search to find individual courses. It also used std::sort to organize the course list before printing.

I selected this artifact for my ePortfolio because it demonstrates my ability to apply algorithms and data structures to a practical problem. The program shows skills in file handling, parsing CSV data, creating structured course records, storing prerequisite relationships, sorting course data, searching for specific records, and evaluating tradeoffs between different data structures. I improved the artifact by keeping the vector for sorted course printing while adding an unordered_map hash table for faster course lookup. This means the program can still print courses in alphanumeric order using the vector, but it can now search for individual courses more efficiently using the hash table. I also improved the program by clearing old data before reloading the file, preventing duplicate entries, validating CSV rows before adding them, skipping incomplete or duplicate course records, checking whether data has been loaded before printing or searching, and adding menu input validation so non-numeric input does not break the program. These enhancements improved both the efficiency and reliability of the original application.

This enhancement helped me meet the course outcomes I planned for this category. It supports Course Outcome 2 because I am explaining my technical decisions clearly through this narrative and through the organization of the enhanced code. It supports Course Outcome 3 because I evaluated the original vector-based solution and improved it using algorithmic principles and data structure tradeoffs. The original vector was simple and useful for sorted output, but searching through it required checking courses one by one. Adding an unordered_map improved lookup efficiency while still keeping the vector for sorting and display. It also supports Course Outcome 4 because I used C++ standard library tools such as vector, unordered_map, sort, file streams, and input validation techniques to improve the program’s functionality and reliability. I do not have major updates to my outcome-coverage plan because this enhancement still fits the Algorithms and Data Structure category as originally planned.

While enhancing and modifying this artifact, I learned more about how different data structures can be combined to solve different parts of the same problem. Originally, the program only used a vector, which made the code easy to understand but less efficient for searching. By adding an unordered_map, I improved the search process without removing the vector’s usefulness for sorted output. I also learned the importance of defensive programming when working with file input and user input. One challenge I faced was making sure the course data was stored consistently in both the vector and the hash table. Another challenge was testing invalid CSV rows, duplicate courses, invalid menu choices, and searches before the data was loaded. These changes helped me see that improving an artifact is not only about making it faster, but also about making it more reliable, easier to use, and safer when unexpected input occurs. Overall, this enhancement strengthened the Course Planner program and better demonstrates my skills in algorithms, data structures, runtime efficiency, input validation, and C++ programming.

Running the project

In plain English: Instructions for a developer who wants to run the program on their own computer.

This artifact is a C++ console application. It does not require Node.js, Angular, MongoDB or Postman.

Applications and tools needed

Visual Studio 2022
Used to open, build and run the C++ solution.
C++ Desktop Development workload
Required in Visual Studio to compile the project.
CSV input file
The file CS 300 ABCU_Advising_Program_Input.csv must stay in the project directory.
  1. Open CoursePlanner.sln in Visual Studio 2022.
  2. Build the solution.
  3. Run the program with Ctrl + F5.
  4. Use the menu to load course data, print the course list, search for a course or exit.

The included CSV file must remain in the project directory so the program can load course information correctly.

Testing and validation

In plain English: The tests I ran to prove each improvement works, including tests with bad input on purpose to make sure the program handles it safely.

These tests confirm that the program loads data, validates input, prints courses in order and uses the enhanced hash table lookup correctly.

1Run the program

  1. Open CoursePlanner.sln in Visual Studio 2022.
  2. Build the solution.
  3. Run the program with Ctrl + F5.

Expected result: The menu displays options to load data, print the course list, print a course and exit.

2Data not loaded validation

  1. Run the program.
  2. Before loading the CSV file, choose option 2 to print the course list.
  3. Before loading the CSV file, choose option 3 to search for a course.

Expected result: The program tells the user to load the course data first.

3Load course data

  1. Select option 1.
  2. Press Enter to use the default CSV file name, or type CS 300 ABCU_Advising_Program_Input.csv.
  3. Confirm that the program reports the course data loaded successfully.

Expected result: The CSV file loads without errors.

4Print course list

  1. After loading the CSV file, select option 2.
  2. Review the printed course list.

Expected result: Courses print in alphanumeric order by course number.

5Valid course search

  1. After loading the CSV file, select option 3.
  2. Search for CSCI300.

Expected result: The program displays the course title and prerequisites for CSCI300.

6Case-insensitive search

  1. Select option 3.
  2. Search for csci300 in lowercase.

Expected result: The program still finds the course, because input is converted to uppercase before searching.

7Invalid course search

  1. Select option 3.
  2. Search for TEST999.

Expected result: The program displays Course not found.

8Menu input validation

  1. At the main menu, type a non-numeric value such as abc.
  2. Then type an invalid option such as 7.
  3. Then type a valid option such as 1, 2, 3 or 9.

Expected result: Non-numeric input shows an invalid input message, invalid menu numbers are rejected, and valid options still work.

9CSV validation

  1. For testing only, add invalid rows to a copy of the CSV file, such as BADCOURSE, ,Missing Course Number and CSCI300,Duplicate Algorithms.
  2. Run the program and load the test CSV file.

Expected result: The program skips incomplete or duplicate course records and continues loading valid records.

10Hash table lookup verification

  1. Load the course data.
  2. Search for a valid course by course number.
  3. Confirm that the search returns the correct course without looping through the vector.

Expected result: The enhanced program uses the unordered_map hash table for lookup while keeping the vector for sorted printing.
