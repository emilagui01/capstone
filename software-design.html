Overview

In plain English: Travlr is a travel booking website. Staff log in to an admin area to add, edit and remove trips. I built it in an earlier class and improved it for my capstone. MEAN stands for the four tools it's built with: MongoDB stores the data, Express and Node.js run the server, and Angular is the part people see and click.

Travlr is a full-stack travel booking web application developed using the MEAN stack: MongoDB, Express, Angular and Node.js. The application includes an Angular administrative interface, a Node.js and Express backend API, MongoDB database integration and JWT-based authentication for protected routes.

This artifact was originally developed in CS-465 Full Stack Development I and is used for the Software Engineering and Design category of the CS-499 Computer Science Capstone.

Enhancement narrative

In plain English: My written explanation, as submitted for the course, of why I chose this project, what I changed, which course outcomes it meets, and what I learned along the way.

Milestone Two: Enhancement One · CS-499 · May 23, 2026

The artifact I selected for the Software Design and Engineering category is the Travlr Getaways full-stack web application. This project was created during my previous term in CS-465 Full Stack Development I, around March and April of 2026. Travlr is a travel management web application built using the MEAN stack, which includes MongoDB, Express.js, Angular, and Node.js. The application includes a customer-facing travel site and an administrator single-page application that allows authenticated users to manage trip records. The original version of the project supported viewing trips, logging in, adding trips, and editing existing trip information through RESTful API communication between the Angular frontend and Express backend.

I selected this artifact for my ePortfolio because it demonstrates several important software design and development skills. It shows my ability to work with a full-stack architecture, create reusable Angular components, connect a frontend application to backend REST API routes, use services for API communication, and apply authentication using JSON Web Tokens. This artifact also represents one of the more complete applications I developed in the Computer Science program because it includes frontend design, backend routing, database integration, authentication, and administrative functionality. These features make it a strong artifact for showing my growth in software engineering and design. For the enhancement, I improved the Travlr administrator application in several specific ways. I added an Angular authentication route guard to protect the Add Trip and Edit Trip pages, so users who are not logged in are redirected to the login page instead of being able to access those routes directly. I also updated the login process so it waits for the actual authentication response and saves the JWT token only after a successful login, instead of relying on a timed delay. To improve usability, I added user-facing error messages for failed login, add trip, and edit trip actions. I strengthened the Add Trip and Edit Trip forms by adding validation rules for minimum field lengths, required dates, valid price formatting, valid image file extensions, and longer descriptions. I also made the trip code field read-only on the Edit Trip page so users do not accidentally change the identifier used to update the trip. In addition, I added Delete Trip functionality by creating a protected backend DELETE route, adding a delete method to the Angular trip data service, and adding a Delete Trip button with confirmation to the trip card component. Finally, I added short comments to the enhanced TypeScript files to explain important logic such as route protection, form validation, login handling, editing trips, deleting trips, and submitting new trip records. These changes made the application more secure, more reliable, easier to use, better documented, and more complete because the administrator side now supports full CRUD functionality: creating, reading, updating, and deleting trip records.

This enhancement helped me meet the course outcomes I originally planned for this category. It supports Course Outcome 2 because I had to explain my enhancement decisions clearly through the code review and this narrative. It supports Course Outcome 3 because I evaluated the original application design, identified weaknesses, and made design decisions that improved the structure and usability of the application. It supports Course Outcome 4 because I used modern computing tools and practices, including Angular routing, Angular services, Express routes, JWT authentication, RESTful API design, and reusable components, to improve the application. It also supports Course Outcome 5 because several of the improvements strengthened the application’s security mindset. For example, the original application hid the Add Trip and Edit Trip buttons when a user was not logged in, but the routes themselves were still accessible if typed directly into the browser. Adding an Angular route guard improved the design by redirecting unauthenticated users to the login page before they could access protected administrative screens.

While enhancing and modifying the artifact, I learned more about how frontend security, validation, backend route protection, and CRUD functionality work together in a full-stack application. One challenge I faced was understanding that hiding buttons in the interface was not the same as protecting the route itself. After testing the application, I saw why route guards are important for a more complete authentication flow. Another challenge was improving the Add Trip and Edit Trip validation so the forms did not accept unrealistic values such as very short text, invalid prices, or image names without proper file extensions. I also had to troubleshoot why validation messages were not appearing at first, which helped me better understand Angular’s form validation behavior and the need to restart the Angular development server after certain changes. Adding Delete Trip functionality was another useful challenge because it required updates across the full stack, including the Express controller, API route, Angular service, and trip card component. I also improved my commenting style by adding short comments that explain the purpose of important methods without repeating what the code already says. Overall, this enhancement helped me improve the Travlr application from a basic working project into a more polished and secure software artifact that better demonstrates my skills in software design and engineering.

Running the project

In plain English: Instructions for a developer who wants to run the project on their own computer.

This artifact can be tested through the Travlr administrator web application. Postman is not required for these tests because they focus on the user interface, route protection, form validation, login flow and admin CRUD features.

Applications and tools needed

Visual Studio Code
Used to open and review the project files.
Node.js and npm
Used to install dependencies and run the backend server.
Angular CLI
Used to run the Angular administrator application.
Web browser
Used to test the Travlr admin interface at http://localhost:4200.

Generated dependency folders such as node_modules were removed to reduce file size, so dependencies must be reinstalled before running the project.

  1. Install backend dependencies from the main Travlr project folder:
    npm install
  2. Install Angular dependencies:
    cd app_admin
npm install
  3. Start the backend application from the main Travlr project folder:
    npm start
  4. Start the Angular development server in a separate terminal:
    cd app_admin
ng serve
  5. Open the admin application in a browser:
    http://localhost:4200

Testing and validation

In plain English: The tests I ran to prove each improvement works. Each one lists the steps and the result that should happen.

These tests confirm that route protection, login flow, validation, CRUD functionality and user-facing error handling work correctly.

1Route guard protection

  1. Start the backend server with npm start.
  2. Start the Angular admin application with cd app_admin and ng serve.
  3. Open the application at http://localhost:4200.
  4. Make sure the user is logged out.
  5. Type http://localhost:4200/add-trip into the browser.
  6. Confirm that the application redirects to the login page.
  7. Repeat the test with http://localhost:4200/edit-trip.

Expected result: Logged-out users should not be able to reach protected admin routes directly.

2Login flow

  1. Navigate to the Login page.
  2. Enter valid login credentials.
  3. Submit the form.
  4. Confirm that the JWT token is saved and the user is redirected to the trip listing page.
  5. Log out and try logging in with invalid credentials.

Expected result: A valid login redirects to the trip listing page. An invalid login displays a user-facing error message.

3Add Trip validation

  1. Log in as an authenticated user.
  2. Go to the Add Trip page.
  3. Enter invalid values: ab for Code, hi for Name, x for Length, a blank Start Date, aa for Resort, abc for Per Person, reef1 for Image Name and short for Description.
  4. Click Save.

Expected result: The form displays validation messages and prevents invalid trip data from being submitted.

4Add Trip valid submission

  1. Go to the Add Trip page.
  2. Enter valid trip data: Code TEST2026, Name Test Trip, Length 4 nights, Start 2026-05-07, Resort Test Resort, Per Person 799.99, Image Name reef1.jpg, Description This is a test trip description.
  3. Click Save.
  4. Confirm that the trip appears in the trip listing.

Expected result: Valid trip data saves successfully and appears on the trip listing page.

5Edit Trip

  1. Log in as an authenticated user.
  2. Click Edit Trip on an existing trip.
  3. Confirm that the Code field is read-only.
  4. Update fields such as Name, Length, Resort, Price, Image or Description.
  5. Click Save.
  6. Confirm that the trip updates on the trip listing page.

Expected result: The trip updates successfully, and the trip code cannot be changed by accident.

6Delete Trip

  1. Log in as an authenticated user.
  2. Create a test trip or choose an existing test trip.
  3. Click Delete Trip.
  4. Confirm the browser confirmation popup appears.
  5. Click OK.
  6. Confirm the trip is removed from the trip listing.

Expected result: The selected trip is deleted only after confirmation.

7Error handling

  1. Stop the backend server while the Angular frontend is still running.
  2. Try to add or edit a trip.
  3. Observe the error message shown in the interface.

Expected result: The application displays a clear error message instead of only logging the error in the browser console.
